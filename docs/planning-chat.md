# 通过聊天调整学习计划

从 Web 左侧「学习对话」进入；概览和课堂也有入口。使用当前空间已检测通过的模型配置，无需单独配置聊天 Key。聊天内容、当前学习需求与本空间能力／复习摘要会发送给该模型，遵循已有授权，调用可能产生费用。

## 日常使用

可以说“每天改成15分钟，先学进程调度，例子贴近面试”“下个月考试，调整复习重点”“补充虚拟内存这一部分”。模型提出受限的目标、时间、期望深度、日期、范围、重点、讲解偏好和阶段路线；后端校验后自动应用。已生效卡片展示真实差异、需求版本和新下一步。模型解释计划时只记录对话，含糊需求先澄清。

单条消息最多4000字符，Ctrl／Cmd＋Enter发送，输入法组合期间不会误发。模型生成期间显示等待状态，校验完成后同时发布完整回复和计划；不是逐token显示。聊天历史默认每页30回合，可加载更早消息。

当前计划右侧显示需求和阶段路线，移动端上下排列。新生成课堂会使用讲解偏好；原有课堂内容不静默重写。改变当前学习内容时，已不属于安排的未完成课堂可以暂存；必要前置课堂保留。暂存不是完成，不增加证据或延后 FSRS。点击「继续原课堂」恢复同一道题，若已有其他未完成课堂则提示冲突。

## 学习证据与跨端

BKT 与 FSRS 仍在所有空间启用。聊天不会提高掌握度、修改算法参数、伪造评分或重排旧卡片的原生到期时间。新增知识点为 unknown／unassessed；旧节点、作答、事件、章节和卡片保留。暂缓某部分只改变当前目标范围，其卡片仍可在复习列表读取。

CLI 本次没有新增交互chat命令；现有 `study-agent plan`、`study-agent next`、`study-agent learn` 使用同一后端需求版本和安排。作答后的动态重排不会覆盖模型生成的路线。全部已掌握时，阶段验证会遵守明确重点；缺少前置证据时仍需先补前置。

## 失败与重试

- 失败／上下文冲突显示「未生效」，原计划保持有效。使用该条消息的重试按钮，沿用原内容与幂等标识。
- 相同键和内容不重复应用；相同键不同内容409；空间内已有处理中消息时，其他消息返回409并等待。
- 刷新后可恢复处理中／失败回合。180秒认领租约过期后可明确重试；普通启动不自动发起有费用的模型请求。
- 模型等待期间可以继续作答；发布读取最新能力。如果教材知识结构、需求版本或所选模型已变更，则本次不应用，重试会使用新上下文。
- 服务器已提交但页面刷新失败时，会提示结果已保存；重读历史即可恢复，不必发送相同修改第二次。
- 登出、删除或归档空间后，迟到模型结果不能重建计划。聊天与修订属于本人空间，永久删除空间会一起移除；常规启动／迁移不清空学习数据。

## 模型与演示范围

兼容聊天与原生文件适配器复用结构化生成能力，不要求工具调用；无新PDF解析器或额外模型。固定演示支持分钟预算、进程重点、面试风格、虚拟内存新增和普通解释／澄清样例；真实需求质量仍取决于所选模型，演示不会在真实调用失败时自动启用。

模型上下文最多最近20个成功回合，历史文本总预算24000字符；需求和路线独立持久化，不随旧聊天裁剪消失。模型上下文不含 API Key、其他空间、未答题参考答案或完整教材正文。新增公开接口使用 Pydantic 响应校验；模型不能通过自由JSON补丁执行代码或修改凭证／授权。

## 升级与验证

迁移0005增量加入聊天回合、学习意图、计划修订及课堂暂存状态。运行 `./scripts/serve.sh` 时自动迁移；已有学习内容保留，不在启动时调用模型。停掉旧版本服务后再启动，以加载新代码。

验收采用临时库、Fake与协议替身，包含真实临时PostgreSQL与Web／CLI HTTP联调，不使用真实用户记录或付费模型。完整结果见[验收记录](acceptance.md)。
