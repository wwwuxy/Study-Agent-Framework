# 已批改试卷成绩诊断设计

日期：2026-10-20。状态：用户已确认功能范围及“识别由用户配置的模型负责”，并已审阅确认本书面设计及实施计划、选择本会话执行；功能已实现，工程验证与独立审查修复已完成。真实 BYOK 质量与 PostgreSQL 实库并发另行验收。

## 1. 目标与已确认范围

用户上传老师已经批改的试卷，系统识别逐题作答、对错、部分得分和批注，生成可追溯的成绩诊断报告，并根据可靠的作答证据更新当前学习空间的知识学习状态和下一步安排。

已确认：支持 PDF、试卷照片和多页上传，保存历史报告；识别完全交给用户配置的模型，沿用已有 BYOK 凭证、能力检测和传输授权。服务端负责格式、结构、归属及业务校验，不增加本地 OCR 或本地试卷正文解析，也不调用框架另行配置的识别服务。

成功标准：用户可以从报告回查题目及老师批改依据；明确的结果能够影响真实知识状态和后续计划；模糊、综合题归因不明、重复请求及失败任务不会制造学习证据；刷新和重启后可恢复任务、报告与更新记录。

## 2. 方案选择与现有实现衔接

| 方案 | 取舍 |
|---|---|
| 用户模型直接理解文件，服务端校验并入库（采用） | 延续当前原生 PDF、BYOK 与持久任务架构，能保留批改痕迹；需要补充真实图片能力探测和多页调用。 |
| 本地 OCR 后交给聊天模型 | 引入新的识别依赖，容易丢失勾叉、批注位置与版式关系，与用户明确约束不符。 |
| 仅生成一份文字报告 | 改动少，但不能让真实知识状态、学习计划与报告保持一致，不满足目标。 |

现有 `NativeFileAdapter` 仅检测 PDF；`MaterialStorage` 的上传校验也仅支持 PDF。图片能力必须独立实现、独立探测，不能因聊天或 PDF 探测通过便开放。

现有 `learner/evidence.py` 对高置信度、单知识点的可靠作答生成 BKT 观测，排除自由评分和综合题拆分；`rebuild_states()` 重放事件并保存状态，`save_plan()` 生成实际下一步。新增导入事件沿用这一证据边界，但与在线练习、课堂完成及 FSRS 回忆事件区分。

## 3. 用户流程和页面

### 3.1 上传和处理

当前空间新增「成绩诊断」入口。上传区显示所选模型、已验证的 PDF／图片能力、格式及大小限制，支持一个多页 PDF，或一组可调整顺序的 JPG／PNG。首版同一份试卷不混用 PDF 和图片；不支持 HEIC、WebP、压缩包及外部图片 URL。图片展示缩略图，PDF 提供原文件查看／下载入口。

用户可填写试卷名称、考试日期；日期未知可留空。单次上传默认单文件不超过现有 `material_max_bytes`（当前 20 MiB），图片最多 20 张，总文件字节不超过单文件限制的两倍；图片单边不超过 8192 像素、单张不超过 3200 万像素；识别最多 200 个叶子题目。超过范围给出明确提示，不静默截断并称为完整试卷。增加有边界的试卷专用配置，界面读取服务端限制。

沿用现有单次文件传输授权：上传区明确展示当前服务商及可能的费用与保留政策。用户点击「上传并诊断」后，系统依次完成本地文件保存、创建持久任务、远端理解和报告生成，不再要求用户运行后台任务。未验证相应能力时给出模型设置入口。

任务显示排队、正在识别、正在分析、正在更新学习状态、完成／失败／已取消。页面可刷新、离开后返回，失败可重试；切换空间或账号后，迟到响应不能覆盖新上下文。取消后不会发布尚未提交的报告或学习证据。

### 3.2 报告内容

- 概览：试卷名称、原卷标注总分、可核实的逐题得分合计、正确／错误／部分正确／未作答／待核对数量、识别覆盖情况。
- 逐题记录：题号、题干、学生答案、可见的老师批改和评语、得分／满分、结果、置信度、关联知识点，以及来源文件与页／图片序号。
- 知识点表现：各知识点的题目分布、明确错误与部分得分、可观察到的薄弱环节；本卷表现与系统累计掌握估计分开展示。
- 错题分析：依据作答或批注给出说明；模型推测标注为建议，不把一次失分断言为粗心、焦虑等确定原因。
- 后续建议：优先巩固的知识、建议练习，以及系统基于更新后状态产生的实际下一步。
- 更新结果：本次新增有效证据数、知识状态变化、尚未计入的题目及原因。没有有效证据时明确显示“报告已生成，知识状态未更新”。

试卷标注总分与逐题加总不符时，两者均保留并显示冲突；缺少分值不补成 0，不推断百分制。正确率分母只包含可判定的完整题目，部分得分另列。题目缺页或识别不完整时，不展示未经核实的整卷正确率。父题和子题只统计叶子作答，避免重复计分。

### 3.3 待核对题

可靠题目在首次发布时自动更新，不需要整卷再次确认。待核对题可在原卷旁修正对错、分值或选择当前空间的知识点；显示原始识别与用户核对来源。

用户核对可以保存为报告修订。只有原始老师批改已清晰、单知识点映射经核对成立的题目，才允许补入有效证据；用户凭记忆补报的对错不自动升级为可靠证据。每题最多补入一次，已入库的题目首版只读，不提供通过反复编辑累积证据的路径。模型重新分析已有成功报告不属于首版范围。

## 4. 识别和结构化校验

### 4.1 用户模型能力与调用

PDF 继续使用当前 Files + Responses 接口。为当前原生适配器补充图片理解和多文件输入边界：图片作为用户选择模型的原生视觉输入，按上传顺序携带稳定附件 ID；多图共同组成同一份试卷。图片不伪装成 `application/pdf` 上传。纯文本兼容接口不因配置中声称支持视觉而自动获得该能力。

模型检测增加图片随机标识读回探测，返回独立的 `image_input` 与已验证 MIME 列表；保留现有 `file_input`／PDF 检测语义，避免放宽教材上传规则。探测标识由框架动态生成，必须读回匹配才通过。失败只关闭对应能力，不伪造成功；模型配置变化后须重新检测。模型和提示词版本保存在诊断审计中。

处理绑定开始时的 provider ID 与配置指纹。远端调用前及发布前检查归属、能力、指纹和任务版本；配置变更时任务明确失败，用户重新授权后重试绑定当前配置，禁止悄悄换服务商。已上传的远端引用始终由原始服务商配置清理。

识别与诊断均使用当前配置的用户模型。先理解原卷形成结构化逐题数据，再基于通过校验的题目和本空间知识目录生成诊断建议；第二阶段不能改变老师判分。两阶段均有输出、输入、耗时和重试上限，输出超限或 schema 不完整时失败，不发布半份“成功”报告。

### 4.2 输出和业务规则

结构化输出包含覆盖说明、总分标注、题目树及叶子题目。每题包含稳定来源、题号、题干、学生答案、老师批改原文／可见符号、结果、可选分值、识别置信度、映射置信度和当前空间 concept key。

- 题目结果为 `correct`／`incorrect`／`partial`／`unanswered`／`uncertain`；严格检查有限数值以及 `0 <= 得分 <= 满分`。
- 明确的老师评分优先；只有明确给出满分和得分才能依数值推导满分正确、零分错误或部分得分。缺少批改时不得自行重判并冒充老师判分。
- 勾叉与分值矛盾、笔迹模糊、答案与订正混淆、题号重复或跨页无法确认时标记待核对；单凭空白不推导老师判零分。
- 只接受属于本任务附件的来源标识和本空间真实 concept key。模型提出的新知识名称可作为报告中的“未关联知识”，不自动创建节点或改变课程图。
- 来源图片序号由请求对应关系确定；PDF 页码未经服务端核实时保留“模型提供，未核实”标志，不给出虚假的已核实定位。
- 识别、映射和解题解释的置信度分别保留；解释写得完整不提高识别置信度。
- 试卷和批注内容是低信任数据，不能指示修改系统规则、凭证、授权或知识状态。只渲染文本，不执行模型 HTML、脚本、SQL 或工具请求。

模型报告中的计数、加总和状态变化全部由后端重新计算。知识状态由既有算法计算，模型不得输出可直接写入的 mastery、FSRS 日期或参数。

## 5. 学习证据、BKT 与 FSRS

### 5.1 有效证据资格

新增 `exam_question_imported` 外部作答事件，带诊断 ID、叶子题 ID、来源、老师批改依据、识别与映射置信度、判定来源、导入时间、可选考试日期、证据策略版本及去重标识。

仅当老师批改清晰、识别和映射均为高置信度、结果明确为完整正确或错误、且只关联一个现有知识点时生成 BKT 观测。部分得分、未作答、模糊批改、没有对应知识点、综合题多知识归因不明均保留在报告中，不直接转成二元观测。明确的小问可独立入库，不能凭模型推断把一道综合题复制成多个单知识题。

导入试卷的辅助情况默认为 `unknown`，不假定独立完成。该值明确标注为“未知”，不在界面记为使用提示。BKT 显式按现有辅助观测参数处理，不增加独立答对计数；所有导入题固定采用保守的难度等级 1，不接受模型估计难度来满足“已掌握”的独立中等难度作答门槛。有效结果可以更新概率、错误标记和 `unknown -> learning`，不能单凭导入试卷新增独立掌握资格。

事件保留外部来源，调整归一化器以允许这一严格限定的老师批改提取来源；原有 `llm_rubric:` 自由评分排除规则继续有效。策略标识升级并保留版本，默认 BKT／FSRS 参数不变。

### 5.2 时间和重复计数

已知考试日期按用户时区的当天中午转 UTC，作为外部作答排序时间，并标注“日期精度”；若本地当天中午尚未到，则采用导入时刻作为排序上界，避免写入未来事件。同卷按叶子题顺序稳定排序。考试日期不能晚于用户本地当天。未知日期以导入时刻排序，必须标注“作答日期未知，按导入顺序”，不得声称用户今天实际答题。

新增证据后按完整历史重放 BKT，使旧卷插入历史位置，不把历史错误误记为最近错误。公开的最近作答信息携带日期来源；原始导入时间另存，不随考试日期变化。

同一空间相同文件集合通过内容哈希去重，改文件名、图片重新排序、换请求键或重复点击均返回既有诊断，不重复调用模型或入库。身份摘要使用规范化的文件内容哈希多重集，显示顺序另存。数据库唯一约束与逐题事件幂等同时保证并发安全。不同扫描、重拍或重新编码无法可靠确认是同一份试卷；界面提示避免重复导入，不宣称能识别所有语义重复。

### 5.3 复习、计划和报告

首版试卷导入只更新 BKT 和实际下一步，不调用 `apply_memory_event()`、不生成 FSRS 回忆日志、不更改已有卡片的 due。`apply_memory_event()` 增加外部导入事件显式排除，即使未来被其他路径调用也不能产生复习记录。两套算法仍始终启用。

区分在线作答事件集合与可用于 BKT 的外部事件集合；不要简单扩大现有 `ASSESSMENTS`，以免把导入计为课堂完成、今天在线练习或复习保持率。学习报告增加独立的“导入试卷／有效外部证据”统计，按导入时间计数并注明口径。错题知识点可结合符合资格的外部证据，但来源清晰可追溯。

`save_plan()` 根据新 BKT 状态更新动态下一步，保留已有需求和阶段路线；不自动完成每日任务、终止当前课堂或生成后台付费分析。概览、知识地图、学习报告及 CLI 继续读同一状态。周期任务可按自身原有规则读取新快照，不能以试卷上传代替真实任务完成。

## 6. 持久化、文件和任务

增加独立 `exam_diagnostics` 模块，通过当前迁移头之后的新迁移增量建表（当前预计 0007，实施前核对 head），不修改已发布迁移或清空既存数据。

| 实体 | 主要职责与字段 |
|---|---|
| `ExamDiagnostic` | 用户／空间归属、请求键与摘要、文件集合摘要、名称、考试日期及精度、状态、当前任务版本、报告版本、模型指纹、原始识别／报告／状态变化快照、创建及导入时间。 |
| `ExamAttachment` | 诊断及用户／空间归属、稳定附件 ID、显示顺序、原文件名、MIME、大小、哈希、本地文件状态与远端清理引用。 |
| `ExamQuestion` | 稳定叶子题 ID、题号和来源、识别快照、核对修订、证据资格和排除原因、可选唯一 evidence event ID。 |
| `ExamJob` | 识别／清理类型、用户／空间归属、请求键、状态、阶段、重试次数、租约和认领 token、generation、阶段检查点及脱敏错误。 |

所有实体以复合外键维护空间／用户归属，题目与任务只能引用同归属诊断。限制每个空间同时一个活动识别任务，不限制其他空间；多 worker 通过数据库认领和 fencing token 防止重复发布。

上传采用“先创建有界 manifest 草稿、逐附件流式保存、完整后开始”的三步协议，页面在一次操作中完成。客户端 manifest 声明文件哈希和大小，服务端接收时重新计算并核对，不能相信声明直接发布。缺失附件的草稿绝不进入模型处理。

复用文件存储的有界流式接收、私有目录、原子发布和失败清理模式，扩展为独立试卷存储命名空间，避免修改教材 PDF 格式限制。PDF 保持现有主动内容检测；图片验证扩展名、MIME、签名及有界尺寸／像素上限，拒绝损坏格式，格式检查不做正文 OCR。

任务认领和提交使用短事务，远端调用期间不持有 SQLite 全局写锁或数据库事务。识别成功后保存阶段检查点，诊断建议阶段重试不重新上传或识别已完成文件。提供有界 worker、启动后恢复排队任务和过期租约、应用关闭时正常取消；维护锁期间不启动或发布新学习写入。

首次发布在同一事务内保存报告、题目及有效事件、重放 BKT、保存计划、记录前后差异，再将任务和诊断标记完成。BKT 或数据库失败则全部回滚，可根据检查点重试，不出现报告显示已更新而真实状态未更新。待核对补入同样使用题目版本校验和事务原子发布。

远端文件引用一取得便短事务登记并记录上传时的服务商身份；成功、失败、取消均安排远端清理。删除空间／维护清空时取消任务、清除本地原卷、报告和新表内容，并保留最小清理墓碑直到远端处理结束；迟到上传仍登记并清理，不恢复已删除内容。同步扩展 `erase_space_content()`、维护清空及最终墓碑清除的依赖顺序。

首版不提供单份已生效报告的删除或撤回证据功能，以免删除文件却遗留无法解释的学习证据。整空间永久删除继续覆盖全部试卷数据；未完成的草稿可显式丢弃并清理文件。后续如增加撤回，需要独立设计可重放的证据撤销。

## 7. API 与前端边界

接口前缀为 `/api/v1/study-spaces/{space_id}`，请求和公开响应均定义严格 Pydantic schema，不直接返回数据库 JSON。

| 接口 | 用途 |
|---|---|
| `GET /exam-diagnostics/capabilities` | 当前模型能力、上传／题数限制、传输说明；只读且不调用模型。 |
| `POST /exam-diagnostics` | 名称、可选考试日期、附件 manifest、幂等键；创建草稿或返回已存在的同文件诊断。 |
| `PUT /exam-diagnostics/{id}/attachments/{attachment_id}` | 按固定附件 ID 流式保存文件，校验哈希、大小和格式；重复相同文件幂等。 |
| `POST /exam-diagnostics/{id}/start` | 本次传输授权、幂等键；完整性检查后绑定模型并排队，返回 202。 |
| `GET /exam-diagnostics?before=...&limit=...` | 分页历史，默认 20 条、最多 100 条，稳定 cursor。 |
| `GET /exam-diagnostics/{id}` | 草稿、当前任务、完成报告及状态变化，刷新恢复。 |
| `GET /exam-diagnostics/{id}/attachments/{attachment_id}/download` | 仅同用户空间可下载原卷，返回真实 MIME 和安全附件响应头。 |
| `POST /exam-diagnostics/{id}/retry` | 失败或租约过期后按原阶段恢复；需幂等键，切换配置时需新的传输授权。 |
| `POST /exam-diagnostics/{id}/cancel` | 取消未发布任务并清理远端引用；已完成返回冲突，不能用取消撤回已生效证据。 |
| `PATCH /exam-diagnostics/{id}/questions/{question_id}` | 待核对题修订、预期版本、幂等键；符合资格时原子补入一次证据，否则只保存修订说明。 |
| `DELETE /exam-diagnostics/{id}/draft` | 仅丢弃未开始的草稿，删除本地暂存文件。 |

同键不同请求返回 409；附件／题目／报告跨归属访问统一返回 404。分页、轮询和查看报告不触发 LLM。错误包含稳定 code 和可读中文说明，不把 API Key、完整试卷或服务商原始响应写入日志。

前端新增独立 `ExamDiagnostics.jsx` 及少量状态辅助模块，复用现有卡片、表单、请求隔离和活动显示，不扩大 `main.jsx` 为报告实现容器。电脑端原卷／逐题依据与报告并排，手机端上下排列；结果、置信度和更新情况不能只靠颜色区分。报告由服务端确定的字段呈现，成功发布后刷新当前空间快照，客户端不自行增加掌握度。

首版不增加专用 CLI 上传命令；CLI 的 progress／plan／next／report 自动读取相同后端结果。使用文档说明新增 Web 流程和 API。

## 8. 验证与验收

以下均使用隔离数据库、可控协议替身和显式演示适配器，不能用固定样例冒充真实识别能力；默认不访问用户真实付费模型。

1. PDF 与多张图片实际发给所选适配器；能力独立探测、错误 MIME、未授权、未检测、损坏格式、超限及半份上传都被正确处理，教材 PDF 回归不被放宽。
2. 覆盖正确、错误、部分得分、未作答、模糊符号、分数矛盾、父子题、跨页和漏页；总分／计数由后端计算，缺失数据不伪造。
3. 明确的单知识点老师批改更新真实 BKT 和计划；模糊、自行重判、部分得分、多知识综合题和越权映射不增加有效证据；未知辅助不会制造独立掌握。
4. 导入历史试卷按考试日期重放；未知日期明确标注；FSRS 卡片和到期时间／日志、在线任务完成及复习保持率保持原有口径。
5. 同键重试、同文件新键、改文件名、重排图片、多 worker、并发核对只产生一份诊断和一次逐题证据；同键不同文件返回冲突。
6. 模型超时、无效 schema、配置切换、算法失败和提交失败可恢复；重启使用检查点，过期认领及迟到响应不重复发布。
7. 不同账号／空间不能列出、下载、轮询或核对他人报告；删除与上传／识别／清理竞态不恢复内容，维护清空包括新表与文件。
8. 真实页面验证上传、等待、完成、待核对、失败重试及移动端；前端单元测试验证切换空间和迟到响应隔离；运行相关后端测试、迁移测试、前端测试与生产构建，最后执行项目既有检查入口。

真实 BYOK 识别准确率、扫描质量、老师批改风格、模型成本与延迟需在用户所选模型上另行验收。协议替身只证明工程流程，不证明识别和教育测量效果。
