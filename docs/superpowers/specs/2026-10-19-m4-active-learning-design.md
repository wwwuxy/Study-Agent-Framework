# M4：主动学习工作台与账号隔离设计

日期：2026-10-19（Asia/Shanghai）。状态：用户已确认功能方向及模型调用方式；本设计待审阅，业务实现尚未开始。

## 1. 用户要求与范围

本版依据用户对 M4 的最新调整：取消新增“提醒设置”和“授权与数据控制”模块，实施 M4 其余功能，并完善账号登录页面和不同账号间的数据隔离。用户已选择：**后台使用已有学习数据生成待办和统计周报；LLM 分析仅由用户点击触发。** 该选择覆盖原规格中针对后台付费模型任务及提醒授权的相关设想。

本次交付：今日任务、计划偏离建议、站内消息、学习周报与目标预测、手动 AI 分析、后台运行记录及分析配额、独立登录／注册路由、跨账号隔离。现有账号、学习资料和记录继续保留，不重新执行 M3 清空操作。

不新增提醒渠道／时段／频率／免打扰设置、授权中心、自动执行暂停中心、数据导出、邮件／短信／微信／浏览器系统通知。现有退出登录、账号鉴权及学习空间删除继续工作。后台站内消息按本次确认的产品行为生成；后台统计、任务协调、周报和通知均不调用 LLM。

代码基线为 `d4a57a1` 加当前未提交的 M2／M3、学习 Chat 和知识脑图。现有 Web 已有登录／注册表单及会话，后端已有用户归属检查；本次完善页面路由、会话体验与新增实体的隔离，不建立第二套账号系统。M3 复核中的历史待验收范围继续单独记录，不用 M4 测试替代真实 BYOK／教育效果验收。

## 2. 架构选择

采用 SQLAlchemy 数据库持久任务队列，复用项目已有租约、幂等和独立 Session 的工程模式；SQLite 支持本地单进程，PostgreSQL 支持多 worker 争抢任务。M4 队列与教材任务分别建模，避免教材上传状态和周期学习任务互相污染。

比较过的方案：Redis／Celery 适合已有消息基础设施的部署，会引入新的运行组件；仅用进程内定时器适合短期演示，缺少持久认领、去重和恢复。本版使用数据库队列，不增加 Redis 或 Celery。

```text
调度器（无模型调用）
  → 持久任务认领 → 数据快照与确定性计算
  → 原子发布每日待办／偏离建议／统计周报／站内消息

用户点击 AI 分析
  → 本人会话和空间校验 → 账号日配额预留 → 受限模型请求
  → 再校验会话／空间／版本 → 保存分析及实际用量

登录账号 → Web／CLI 共用鉴权 API → 本人的空间、待办、消息和报告
```

后台持续运行依赖服务进程存活；不安装系统常驻服务，也不启动第二个真实8000服务。管理员可通过部署配置关闭 M4 worker；普通用户不新增暂停／授权设置页。

## 3. 时间、调度与恢复

- 使用 `zoneinfo` 解释现有 `User.timezone`，默认 Asia/Shanghai；数据库存 UTC 时间，保存计划／周报所用的时区快照。无效历史时区明确标注回退到默认值，不能令整批调度失败。
- worker 启动时检查当前日期及最近一个已结束自然周，此后默认每60秒协调一次。自然周为账号时区周一00:00至下周一00:00，使用左闭右开区间处理夏令时。
- 当天计划首次生成后，继续按最新学习证据／意图版本协调；不等到下一天才响应已完成课堂、资料新增或 Chat 调整。刷新入口可请求立即协调，不触发模型。
- 服务停机后只补当前日计划和最近一个已结束周的周报，不回填停机期间每一天的提醒。周期键与唯一约束负责去重，不依赖进程内“已执行”标记。
- 现有账号没有时区修改入口，本次不新增提醒设置来承载该功能；未来由其他可信入口变更时区后，新周期按新时区计算，同一用户／空间／当地日期不重复建计划，已发布历史保留原时区。
- M4 worker 遵守已有维护标记；维护期间停止认领／发布，空间归档或删除后不再生成学习任务及消息。不能自动重建已删除空间。

## 4. 今日任务

### 4.1 生成规则

每个可用空间每天形成一份计划，依据最新学习意图、课程依赖、BKT 状态、FSRS 卡片及截止日期计算，保存依据、生成时刻和需求版本。

1. 未完成的活动课堂优先恢复，保留原题，不重新生成重复课堂。
2. 复用现有推荐策略选择主学习行动；符合先修条件的到期复习可填入剩余预算。
3. 每日主动安排最多6项，建议时长之和不超过该空间 daily_minutes；不假设完成第一项就已经掌握，也不把未满足前置的后继知识预先安排为可执行任务。
4. 所有到期复习均可形成待安排记录；超出预算或先修不足的项目显示“待安排／前置待补”，与当天已承诺预算区分，不能假装已纳入当天计划。
5. 同一复习周期以卡片ID及最近原生日志／last_review组成稳定键。完成复习、进入下一轮后才产生下一周期，不能每次轮询都新建一项。

协调保留已完成、已跳过及正在进行的任务；仅刷新尚未开始的安排。需求变更导致目标离开范围时，旧待办标记 superseded，原课堂、证据和卡片继续保留。

### 4.2 状态及执行

任务状态为 `pending / in_progress / completed / skipped / postponed / superseded`，另以阻塞原因表示预算或前置限制。新任务不产生学习证据。

- **开始**：重校验本人空间、当前范围／先修和复习周期，调用既有学习／诊断／复习服务，关联实际课堂或题目，返回现有课堂展示结构。任务ID派生稳定请求键，重复点击恢复同一执行结果。
- 当前推荐或复习周期已变时返回可理解的冲突并刷新；不静默创建不同概念的题目。存在另一未完成课堂时先继续原课堂。
- **完成**：由真实任务完成事件或所关联诊断题全部提交后确认；“读过”或手动勾选不能替代作答。若提供完成按钮，它只请求服务端核对条件，条件不足不改变状态。
- **跳过**：只改变待办，不制造成功证据，不修改 FSRS 到期时间。
- **改期**：保留来源任务及历史；次日任务协调重新检查预算／依赖，避免同一复习周期同时有两个可执行待办。
- Web 从待办进入现有课堂；CLI 提供列表、开始、跳过与建议处理入口，使用相同 API，不在客户端计算状态。

## 5. 学习中断与计划偏离建议

确定性规则生成建议，并展示触发依据：

- 距最近真实学习行为至少3个当地日期：提示恢复学习；从未学习的账号显示“尚未开始”，不虚构中断天数。
- 至少2项未完成的历史计划任务或到期复习总建议时长超过当天预算：提示拆分或减量。
- 按当前速度推算超过目标日期，或目标日期已过仍有未达标知识：提示调整排期。

建议状态为 `pending / accepted / skipped / expired`，同一原因与有效周期去重。接受时重新检查需求／证据版本；过时建议不能覆盖较新的 Chat 调整。

接受“减量／改期”仅修改当日／后续待办安排，不擅自更改用户总目标、daily_minutes、BKT 或 FSRS 日期。较大需求变更继续由现有学习 Chat 接收用户明确要求。任务列表和建议都允许人工跳过，不能把未响应当作接受。

## 6. 站内消息

仅实现站内消息列表、未读数、标为已读及定位来源。消息类型包括复习到期、计划偏离、周报已生成；当日多项到期复习合并成一条摘要，新增项目更新同一摘要，不重复刷屏。

消息与来源结果在同一发布事务内写入；唯一事件键确保 worker 重试或服务重启不会重复通知。已读状态不因重复协调重置。链接由服务端允许的类型和对象ID构造，不能由 LLM 提供任意跳转地址。

原始到期列表继续可查；消息未读不阻断学习。空间删除同步移除相关消息及内容，迟到任务不能重新插入。账号只能读取／标记本人的消息。

## 7. 每周总结与目标预测

- 周报按空间、账号当地自然周持久保存，沿用现有可靠证据筛选与事件重放方法。新增长期可回看的自然周记录，保留现有滚动7／30天报告。
- 包含独立／辅助／待核实作答、知识状态变化、有效证据、近期错误、到期复习、当天计划任务完成与跳过情况，保存分子／分母与统计区间。
- 没有记录时显示空状态和原因，不能以0%冒充缺少分母的统计结果。
- **目标预测**使用最近28天每周净增加的已掌握知识点速度；至少两个完整周且纳入的各周均为正向净增长才给出估计范围，以各周速度的最小／最大值计算剩余周数区间。存在停滞、回退或不足两个完整周时返回无预测及理由，不删除低速周来制造乐观结果。
- 预测同时显示剩余范围内知识点数、样本周数、速度、截止日期及不确定性，不输出“通过概率”等未经校准百分比。已达标时明确完成当前知识范围；知识范围变更后旧预测保留历史快照并标示版本。
- 当前自然周可读取即时统计预览，历史周报以已结束周的数据快照为准；后台首次补报不会重演多周消息。

## 8. 手动 AI 分析与配额

用户可在今日任务或周报点击“AI分析”。请求限于本人当前空间／指定报告，仅发送必要的目标、受限的课程摘要和统计，不发送 API Key、其他账号／空间的数据、未答题答案或完整教材正文。模型输出为解释与建议，不直接更新计划、成绩或卡片。

采用准备、远端调用、发布三个阶段，复用已有纯数据模型调用边界。每个数据库阶段使用独立 Session；远端等待期间释放锁。发布前复核登录会话、空间状态、需求版本及来源报告版本，冲突时本轮分析不应用，原统计仍可查看。刷新可恢复处理中或失败结果。

部署级默认配额：每账号每UTC日10次分析尝试、100000 Token预算、每次最多1500输出Token；均可通过环境变量调整。所有空间共享本人配额，以UTC日分桶避免切换时区重复获得额度。界面显示统计区间及适用范围：这些限制只管理 M4 手动分析，不冒充已覆盖现有课堂、教材和学习 Chat 的全部费用。

- 调用前在账号级事务内预留次数和 Token 额度，并发请求不能各自读到相同剩余额度后重复放行。
- Token预留使用完整实际请求（包括系统提示与JSON Schema）的UTF-8字节数作为保守输入估算，加输出上限；记录该计算口径。请求体有固定大小限制，模型请求携带输出上限，M4分析关闭适配器内部网络／结构修复重试。
- 服务商返回可靠 usage 时按实际值结算，保留预留、实际、缺失标记和超额情况；usage缺失或超时结果不明时保留保守占用，不能记作零消耗并退款。
- 达到配额后拒绝新分析，统计周报与每日待办继续正常生成。供应商不遵守输出限制或少报用量时，应用侧配额不能承诺其账单的绝对上限。
- 重复请求沿用幂等键返回原结果；失败重试必须由用户点击、形成可区分的新尝试并重新预留，不自动再次付费。
- 展示请求次数、实际／预留Token及状态。未配置价格时货币费用显示“不可用”，不虚构人民币或美元金额；现有普通教学调用默认行为保持兼容。
- 登录失效、空间删除或旧租约失效时不发布学习内容；已发生或不明的模型消耗继续占用账号当日额度。删除空间不能重置账号累计用量来绕过配额。

## 9. 持久化与归属约束

新增增量迁移0006，至少包含下列实体；所有公开输出通过明确的 Pydantic 响应模型校验。

| 实体 | 关键归属／唯一约束 |
|---|---|
| PeriodicJob | user_id、space_id、kind、period_key／协调版本唯一；状态、下一运行时间、租约token、尝试数、错误 |
| DailyPlan | user_id＋space_id＋local_date唯一；时区、需求版本、预算及依据快照 |
| DailyTask | 归属同一DailyPlan和空间；稳定任务／复习周期键；实际执行对象、状态及改期来源 |
| LearningSuggestion | 本人空间＋原因／周期唯一；依据版本、候选修改、处理状态 |
| InboxMessage | 本人空间＋event_key唯一；消息类型、来源对象、已读时间 |
| WeeklySummary | 本人空间＋当地week_start唯一；时区、区间、来源版本、统计与预测 |
| AnalysisRun | 本人空间＋请求幂等键唯一；来源版本、处理状态、租约、模型配置指纹、用量及结果 |
| AnalysisDailyUsage | user_id＋UTC日期唯一；尝试次数、预留／实际Token及未知占用，不能由空间删除重置 |

每个空间实体使用 `(user_id, space_id)` 复合外键指向空间归属，任务到计划／课堂的关联使用空间内复合约束。API不接受客户端指定 user_id；所有对象由认证会话推导归属，跨账号返回404，未登录返回401。

学习空间永久删除服务扩展至新增依赖，移除待办、建议、消息、周报和分析正文，取消队列并使租约失效。保留不含学习正文的账号日累计配额。历史维护清空机制也要认识新表以保持工具兼容，但本次实施和验证不对真实数据运行清空命令。

## 10. 可靠执行与事务边界

队列状态为 `queued / running / retry_wait / succeeded / dead_letter / cancelled`。认领时写随机租约token及截止时间，只有当前token能发布；过期运行可被重新认领。发布先检查用户、空间、租约及当前输入版本。

默认三次执行尝试，失败后按30秒、120秒退避，最终进入死信。运行面板显示可理解的错误码及失败原因；仅本人可手动重试非付费后台任务。手动AI分析不受该自动重试机制驱动。

重复周期创建、并发认领、超时迟到和发布回滚依赖数据库唯一约束及条件更新处理，不只依靠内存锁。PostgreSQL使用短事务行锁／跳过已锁任务；SQLite使用单实例应用锁保护短数据库阶段。锁顺序统一为User→StudySpace→Job／业务对象→配额。

统计计算在线程中处理纯数据，Session不得跨线程、跨事件循环或进入模型调用。现有教材 worker 和 M4 worker 独立管理生命周期。服务退出停止循环并等待有限清理；中断的租约供下次恢复。

## 11. 页面与登录流程

- **今日任务**：日期、空间、预算、优先任务、到期待安排项、开始／继续／跳过入口、偏离建议及接受／跳过操作。
- **站内消息**：未读标识、类型、时间、标为已读、跳转到本人任务或周报。
- **学习周报**：自然周选择、统计、来源依据、目标预测范围及手动AI分析；保留滚动报告入口。
- **后台运行**：本人各空间的作业状态、错误、重试、分析记录和配额，分页查询；无管理员全账号视图或原始异常堆栈。
- 页面延续当前配色与响应式布局，移动端卡片纵排。新页面按登录用户＋空间建立请求作用域，登出／换账号／换空间使旧响应失效。
- **`/login`、`/register`**：抽取现有表单成为独立可访问页面，支持密码确认、错误提示、重复提交防护和正确autocomplete；刷新直达不404，浏览器前进后退状态一致。登录后进入工作台，已有有效会话访问登录入口直接回到工作台。
- 未登录访问工作台进入登录页；会话失效时清理旧账号页面状态和凭证缓存，返回登录页。退出必须服务端撤销成功后清空状态；失败提示错误，不能只清前端假装退出。
- 复用现有用户名、密码哈希和HttpOnly Cookie，不增加第三方登录、找回密码或管理员账号。模型凭证仍按账号加密存储，不在前端共享。

## 12. API与CLI边界

新增命名空间 `/study-spaces/{id}/daily-plans`、`/tasks`、`/suggestions`、`/weekly-summaries`、`/analyses`；账号级 `/inbox`、`/activity-jobs`、`/analysis-usage`。GET只读取，显式刷新／开始／跳过／接受／重试为写操作，均鉴权并校验Origin。

列表默认每页30、最多100，按稳定时间与ID游标翻页；输出不包含密钥、Session、任务内部租约、错误堆栈或模型上下文中的答案。幂等键由已登录用户作用域和空间共同隔离，相同键不同正文返回409。

CLI增加今日任务、任务开始／跳过、建议处理、站内消息、自然周报、AI分析和运行记录／用量入口；分析命令必须显式调用，普通查询命令不能触发付费请求。现有命令及JSON模式保持兼容。具体路由和命令参数在实施计划中逐项固定。

## 13. 验收要求

1. 无模型配置或供应商离线，后台今日任务、统计周报、站内消息仍能生成；调用计数为零。
2. 固定时钟验证当地跨日、自然周、夏令时、无效时区回退、离线补偿和时区变更去重。
3. 并发认领、进程中断、租约过期、重试、死信和手动重试不重复发布任务／消息；已读状态保留。
4. 每日预算不超排、先修约束有效、旧课堂恢复同一道题，真实学习完成后自动更新待办；跳过／改期不改变BKT及FSRS。
5. 建议可接受／跳过，旧建议不覆盖新Chat意图；目标预测有依据，空分母／不足数据明确说明。
6. 手动分析两个数据库阶段之间释放锁；预算并发、跨空间共享、缺usage、超时、重复请求和显式重试正确；不因重启自动付费。
7. 两个独立账号验证全部新旧数据域：空间、模型、文件下载／任务、题目／答案、Chat、待办、消息、周报、后台作业和用量。互猜ID、伪造父对象、沿用相同幂等键均不能越权。
8. 登出／会话过期／账号切换期间的晚到读取与模型结果不能覆盖下一账号页面；后台任务只能使用其空间所属账号配置。
9. 迁移保留现有账号和学习数据；删除空间或维护标记存在时，后台不复活内容。删除不会重置账号日配额。
10. SQLite及独立临时PostgreSQL全量回归、CLI真实HTTP、桌面／390px页面、独立登录路由刷新、生产构建、OpenAPI和分发检查通过；全部使用隔离数据与Fake／协议替身，不调用真实付费模型。
