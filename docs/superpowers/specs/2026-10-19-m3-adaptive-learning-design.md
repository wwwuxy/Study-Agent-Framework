# 阶段三：学习者建模与自适应提升设计草案

> 已被用户的新要求取代：完整开源 BKT + FSRS、所有空间统一启用、清空旧学习空间和记录。当前设计见 [开源 BKT + FSRS 全量接入设计](2026-10-19-m3-open-source-bkt-fsrs-design.md)。下文仅保留为旧草案，不作为实施依据。

日期：2026-10-19（Asia/Shanghai）。状态：待用户审阅，尚未实施。

依据：`StudyAgent_Framework_Development_Spec.md` 第 535–559 行的九项任务、五项验收标准。代码基线为 `d4a57a1` 加当前工作区，已有流式资料传输和 `0003` 永久删除空间迁移。本草案不改动现有业务代码、用户数据库、模型凭证或运行中的学习空间。

## 1. 目标与范围

用户希望依据已有作答证据改善掌握估计、安排复习、选择下一步任务，并在 Web 和 CLI 查看理由与学习报告。完成标准是阶段三九项功能均有实际入口和可重复验证的证据，而不只是添加一个 BKT 函数。

沿用同一个 FastAPI 后端与事件库，保留已有账号、学习空间、课堂、答题和教材记录。PDF 仍由用户配置的 LLM 原生文件 API 理解，不增加独立远端解析服务或本地正文提取。阶段四的主动通知、周期后台调度不在本次范围内。已有 M2 真实服务验收缺口继续单独记录。

## 2. 方案比较与建议

| 方案 | 做法 | 取舍 |
|---|---|---|
| A，建议采用 | 在现有后端增加可插拔 BKT、独立的版本化间隔复习策略、可解释推荐和离线评测 | 保持部署简单，可逐项手算和重放验证；首版复习策略明确为启发式，不冒充 FSRS |
| B | 使用第三方 BKT 与 FSRS 完整库实现估计和调度 | 可利用现成拟合与调度能力，但仍须适配提示、多知识点、去重和历史证据；额外依赖及版本兼容范围更大 |

建议 A。规格要求首个估计器为 BKT，间隔复习“可参考 FSRS”，没有要求首版必须复刻 FSRS。架构为今后替换复习算法保留明确接口。

## 3. 证据与 Q-Matrix

新增统一证据规范化模块，供 BKT、复习、推荐和报告使用；`rules_v1` 保留原计算语义，避免旧空间静默改变。

- Q-Matrix 使用每道题与知识点的显式 0/1 映射，沿用 `AssessmentItem.data.concept_keys`，对外提供查询接口和映射版本。不是从模型回答文本临时猜测知识点。
- 新作答事件保存题目映射、题型、难度、评分器、置信度、辅助等级和证据策略版本的快照。历史事件不回写；重放历史记录时采用显式标注的旧格式兼容路径。
- 以题目 ID 去重。重放同一题不会再次增加独立掌握证据；同一请求幂等返回原结果。
- 仅高置信、可归因的单知识点作答进入 BKT；低置信或未知判分不更新后验。阅读、上传、查看报告、请求推荐均不产生掌握证据。
- `none` 为独立作答；服务端已有提示事件必须把辅助等级至少提升为 `hint`。`solution` 不作为掌握更新证据。
- 多知识点题保存综合表现和待诊断标记，不把一次综合错误归因到全部知识点，也不凭综合答对直接将全部知识点升为已掌握。
- `llm_rubric:*` 可显示为待核实表现，不进入 BKT 的掌握判定和复习成功证据；保留既有保守边界。

## 4. 可插拔估计器与版本

模块拆分为注册表、`rules_v1` 兼容入口、`bkt_v1`、参数规范与证据规范化。注册表按确定的版本选择算法；API 不接受任意模块名或可执行代码。

每个空间选择估计器和参数版本。旧空间迁移后仍为 `rules_v1`；新空间默认 `bkt_v1`。两种算法均提供只读比较，显式切换后才更新该空间的状态缓存和学习计划。

### 4.1 BKT 更新

使用四参数 BKT：初始掌握概率 `L0`、学习转移概率 `T`、失误概率 `S`、猜对概率 `G`。初始实验参数为 `L0=0.2, T=0.1, S=0.1, G=0.25`，参数集版本 `bkt-defaults-v1`，状态为未做真实用户校准。参数必须有限且在合理概率范围内，并满足已掌握的答对概率高于未掌握。

独立作答使用标准贝叶斯更新，令观测前状态为 `p`：

```text
P(correct) = p * (1-S) + (1-p) * G
正确后的观测后验 = p*(1-S) / P(correct)
错误后的观测后验 = p*S / (p*S + (1-p)*(1-G))
下一状态 = 观测后验 + (1-观测后验)*T
```

提示辅助使用明确版本化的弱证据扩展：以权重 `w=0.35` 缩放观测似然的对数比，学习转移率使用 `w*T`；`w=1` 退化为标准 BKT。辅助正确对后验的提升低于相同条件下的独立正确，且不增加独立正确计数。该扩展和默认权重是本项目策略，不声称由真实数据拟合。

没有有效证据时，对用户返回 `unknown` 和空掌握估计，不把先验当作已测能力。标记 `mastered` 仍要求至少两道不同题、独立、高置信、确定性判分、难度至少 2 的正确证据；另要求 BKT 后验至少 0.8，且最近有效证据不是错误。否则为 `learning`。估计不因时间经过而自动清零。

### 4.2 输出与重放

保留已有 `status`、`mastery_estimate`、`evidence_count`、`independent_correct_count` 等字段，新增：

- 请求与实际采用的估计器版本、参数版本、证据策略版本；
- 输入证据窗口起止、数量及摘要哈希，固定按事件时间和 ID 排序；
- 预测下一次独立单知识点表现的内部估计，以及 `calibration_status`；
- 证据支持等级 `low/medium/high`，明确这是证据数量和质量标签，不是统计置信区间。

首版窗口为全部保留历史，避免滚动截断丢掉提示、去重或先前证据。比较接口采用相同事件截面，返回两种算法结果与推荐差异，不修改事件或活跃状态。

合法 BKT 配置遇到可识别的数值计算异常时回退到 `rules_v1`，显式返回回退原因；非法算法或参数版本在切换请求中直接报错。不得静默伪造 BKT 成功。

## 5. 独立的间隔复习

引入 `interval_v1` 调度器，单独存储每个知识点的复习阶段、最近复习时间、到期时间和失败次数，不复用掌握概率字段。

- 首次确定性、独立、高置信、单知识点答对后建立复习状态，初次间隔 1 天。
- 成功复习的间隔依次为 3、7、14、30、60 天，之后保持 60 天；错误、提示辅助完成或需要看答案后回到 1 天。低置信判分不延长间隔。
- 到期计算以实际完成时间为基点，使用服务端 UTC；展示转换为用户时区。时间通过可注入时钟测试。
- 到期仅提高推荐优先级，不修改知识掌握状态。报告展示“到期／逾期多久”，首版不提供未经校准的记忆保持百分比。
- 每次复习生成新的题目并关联复习会话；不会将已经作答且已显示答案的旧题作为新独立证据。
- 一次提交统一完成批改、`review_submitted` 事件、估计重建、复习时间更新和计划保存。失败整体回滚；重复提交不重复延长间隔。
- 复习列表查询不生成题目、不调用模型、不写学习事件。用户开始复习后才生成内容；优先恢复当前未完成的复习。

这里的间隔和重置规则是本项目的透明启发式，算法名称不使用 FSRS。后续若替换 FSRS，须单独版本化、迁移和评测。

## 6. 自适应推荐与教学模式

新增 `policy_v2`，规则顺序可解释、同一状态和时点结果确定：

1. 恢复未完成任务，不因刷新重复生成课堂或题目。
2. 先过滤前置知识尚未达到可靠掌握的候选，禁止只因高目标权重绕过前置门槛。
3. 对可执行候选综合重要性、掌握状态、证据不确定性、复习逾期程度和可用时间打分；分项分数随推荐返回。临近目标日期可调整预算排序，不能降低证据或前置要求。
4. 对关键未知概念优先诊断；诊断预算消耗按不同题目／概念记录，避免复用已经完成的初始诊断导致循环。
5. 误区或近期单知识点错误进入误区修复，已有部分证据进入定向练习，证据充分后安排迁移测试或阶段评估，到期候选进入复习。

动作保留现有值，并增加 `REVIEW`；`ASSESS` 通过 `teaching_mode` 区分 `transfer_test` 和 `stage_assessment`，其他模式为 `first_learning`、`misconception_repair`、`targeted_practice`。复习独立标记 `spaced_review`。

生成讲解与练习时，将模式、目标知识点、难度意图和推荐理由传给现有 LLM 教学接口，并验证返回题目映射。迁移／阶段题要求不同题目情境；是否真正具备迁移测量效度仍需人工与真实数据验证，不能仅凭模型自报认定。

`GET /next-action` 和 `GET /plan` 使用相同的推荐函数及同一请求时点计算到期状态，避免隔天仍显示旧计划；GET 不产生模型调用或完成事件。持久计划保留最近写入时的快照和 `as_of`，响应中明确展示当前计算时点。

## 7. 用户画像与报告

报告由数据库和重放结果确定性生成，不额外调用 LLM：

- 知识点按模块的状态分布、证据数量、独立和辅助作答统计；
- 最近 7／30 天的有效作答、错误、待诊断概念和状态变化，截止点按事件重放计算；
- 易错题与误区，区分确定性错误和模型待核实评价；
- 到期复习、近期完成任务、下一步推荐及可回查事件依据；
- 当前算法、参数版本、回退或未校准提示。

Web 不显示如“掌握 97.43%”的高精度能力承诺；优先展示状态、证据数量和变化。没有足够证据时明确为待诊断。BKT 的内部数值可在结构化诊断结果中返回，并标注未校准。

任务完成以课堂已记录阅读且关联练习均已提交为准；新增 `learning_task_started` 和 `learning_task_completed` 事件，保持幂等，二者不更新掌握。历史课堂可统计现有完成状态，但没有历史开始／完成事件的周期不伪造当期完成率。

## 8. 数据结构与迁移

在当前迁移链之后增加 `0004`，实施前再次核对 HEAD，避免与其他工作区增量冲突：

| 结构 | 内容 |
|---|---|
| `study_spaces` 增量 | `estimator_version`、`estimator_parameter_version`；数据库迁移默认规则版本以兼容旧空间，新建接口显式选 BKT |
| `review_states` 新表 | 用户、空间、知识点，调度版本、间隔阶段、到期和最后复习时间；空间／知识点唯一 |
| `review_sessions` 新表 | 用户、空间、知识点、课堂和题目关联，开始请求键、原到期周期、状态；同知识点仅允许一个活动会话 |
| 现有 JSON 增量 | 题目 Q-Matrix 版本、事件证据快照、估计状态元数据、推荐分项及教学模式 |

新表使用复合外键保证空间归属，查询始终按登录用户和空间过滤。新事件继续遵守 append-only；永久删除空间时按依赖顺序清理复习会话与状态，不使已删除资料或学习记录重新出现。

迁移只增加字段和表，不批量覆盖用户估计、不改历史事件、不启动模型任务。旧空间比较或切换时才重算；切换与计划更新在同一事务中完成。降级删除阶段三派生结构前须提示会丢失新复习安排，原学习事件继续保留。

## 9. 后端、Web 与 CLI 入口

所有业务逻辑只在后端实现。建议新增接口，前缀均为 `/api/v1/study-spaces/{id}`：

| 接口 | 行为 |
|---|---|
| `GET /q-matrix` | 返回空间内题目与知识点映射，不泄露未作答题的答案 |
| `GET /estimators/compare` | 相同事件截面下只读比较规则与 BKT，无模型费用 |
| `PUT /estimator` | 校验版本、显式切换并原子重建状态和计划；同一配置重复设置不重复制造证据 |
| `GET /reviews` | 返回到期／未来复习状态与当前未完成会话，无模型调用 |
| `POST /reviews/start` | 用户显式开始某个到期知识点的复习，带幂等键；返回或恢复会话与课堂 |
| `GET /reviews/{rid}` | 恢复属于当前用户空间的复习会话 |
| `POST /reviews/{rid}/submit` | 提交复习答案，调用统一作答服务并校验会话与题目匹配 |
| `GET /report?days=7` | 7 或 30 天学习报告，含生成时点与证据覆盖说明 |

保留 `/attempts`，抽取统一作答服务。复习题无论从通用提交还是复习提交入口进入，都进行同样的会话校验、复习更新和幂等处理，不能绕过调度或重复加分。`POST /lessons` 遇到 `REVIEW` 动作时复用同一会话生成逻辑，避免 Web、CLI 各自创建另一套复习题。

Web 增加复习与学习报告入口，概览显示到期数量和推荐理由；设置中提供估计器比较／切换，展示旧、新结果与未校准提示。遵循现有异步隔离机制，切换账号／空间后的迟到响应不能覆盖当前页面。

CLI 增加 `report --days 7`、`review list/start/submit`、`estimator compare/use`，保留 `progress/next/plan/learn`，支持同样的 `--space`、`--json` 和会话隔离。终端人工输出使用状态和证据解释；原始概率仅在明确的结构化诊断结果中呈现。

## 10. 评测与校准接口

新增独立、无网络的评测模块与命令行脚本，不接触真实模型 Key，不默认读取用户数据库。

- 固定版本数据集包含学习者序列、知识点、题目、辅助等级、正确性和时间；清单记录来源、版本、固定种子、划分规则和内容哈希。
- 仓库首版数据集为框架自有合成数据及人工边界案例，明确不能证明真实教育效果。实际用户数据必须另行明确导出授权，不把个人学习记录提交到 Git。
- 每条下一题预测先于本题观测更新，按学习者划分拟合／验证／测试集，避免同一学习者和未来答案泄漏。
- 输出下一题预测 Brier score、log loss、固定阈值的误判率及混淆计数；报告两种估计器在同一输入上的对比，不预设 BKT 必须优于规则。
- 复习后保持率仅统计有真实延迟复习作答的合格记录；任务完成率仅统计有完整开始／完成事件的任务。分母为零时返回空值和原因，不能写成 0% 或 100%。
- 提供参数拟合函数和离线入口：在预定义有界参数网格上最小化训练序列的预测损失，使用验证集选择候选，仅最后一次评测测试集。数据不足或仅单一结果类别时输出无法校准，不制造参数有效性结论。
- 拟合输出包含参数、数据版本、分割、指标和 `candidate` 状态，不自动替换正在使用的参数；发布参数需要版本化登记并显式选择。

## 11. 验证与阶段完成标准

功能测试优先验证真实风险与需求，不用只重复公式实现的测试充数：

1. 手算 BKT 序列；独立正确、提示正确、独立错误的差异；无证据、低置信、LLM 判分和多知识点归因边界。
2. 相同事件分别按规则与 BKT 重建；原事件数量和内容不变；重复请求、重启、模型切换和估计器切换不重复计分。
3. 固定时钟验证复习到期、完成后调度、辅助作答回退、低置信不延期；久未登录只影响复习，不清零掌握。
4. 多级前置过滤、未知诊断预算、推荐理由与时间预算；未完成课堂恢复；报告、计划和当前推荐一致。
5. 复习生成中断、重复提交、并发切换、永久删除、用户和空间隔离；SQLite 与真实 PostgreSQL 均验证。
6. 带既有记录的迁移、升级／回滚边界、Alembic metadata 一致性；不在用户现有数据库做试验。
7. 评测集合版本和划分不变；不存在当前答案泄漏；空分母和不够校准的数据有明确结果；保存规则与 BKT 的实际对比产物。
8. Web 桌面／移动端和独立 CLI 流程：比较、切换、学习、到期复习、报告、重登恢复；生产构建和完整现有回归通过。

五项原规格验收必须分别留下证据。合成数据评测通过只能证明算法实现与评测流程可运行，不等于真实用户效果已经校准或提升。README、中文／英文说明、OpenAPI 和验收记录按实际结果更新，不提前标记 M3 全部完成。
