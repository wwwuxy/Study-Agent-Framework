# 阶段三：开源 BKT + FSRS 全量接入设计

日期：2026-10-19（Asia/Shanghai）。状态：用户已确认本版设计；实施计划待审阅，尚未实施。

依据：开发规格阶段三及用户本轮明确要求。用户选择复用完整开源算法，所有学习空间必须同时启用 BKT 和 FSRS；已明确授权“清空全部学习空间和记录，在现有仓库重建相关功能”。这取代前版的手写 BKT、启发式间隔、旧空间沿用规则和算法开关方案，也取代原规格中保留旧规则回退的要求。

代码基线为 `d4a57a1` 加未提交工作区，包括资料流式传输和 `0003` 永久删除空间迁移。本轮只修订设计；尚未清空真实数据、安装产品依赖或修改业务实现。

## 1. 范围和用户可见结果

- 所有可用空间统一用 pyBKT 估计掌握情况、py-fsrs 安排复习，无逐空间开关、无旧规则回退。
- 当前已有学习空间及学习记录全部清空，不迁移旧规则状态，不做双估计器比较。
- 保留仓库、账号、认证、模型配置和密钥、Web／CLI、LLM 教学及原生 PDF 文件接口。
- 空间关联的教材原文、章节、概念、向量、计划、课堂、题目、答案、事件及学习调用记录随空间清理；远端原文沿用可重试删除流程。
- 仍交付 Q-Matrix、自适应推荐、教学模式、报告、校准入口和版本化评测，不只安装依赖。
- 不增加独立远端 PDF 解析、本地正文解析、OCR 或 Embedding 模型。BKT 统计计算与 FSRS 调度不属于文档理解或本地 Embedding。
- 阶段四通知与周期调度不在本次范围内；M2 真实文件服务验收继续单独记录。

## 2. 开源实现及复用边界

| 功能 | 选择 | 实际复用 |
|---|---|---|
| 知识追踪 | [CAHLR/pyBKT](https://github.com/CAHLR/pyBKT)，候选 `pyBKT==1.4.3` | 库的推断、状态追踪和 EM 拟合；用已有观测类别能力区分独立与辅助证据，不自行重写后验公式 |
| 记忆与复习 | [open-spaced-repetition/py-fsrs](https://github.com/open-spaced-repetition/py-fsrs)，候选 `fsrs==6.3.2` | 完整 Scheduler、Card、ReviewLog、四级评分、学习／复习／再学习阶段及原生序列化 |
| 参数优化 | 两库的原生接口 | BKT 原生 EM；FSRS 官方 optimizer extra；在线答题不临时训练参数 |

版本依据：[pyBKT 发布记录](https://pypi.org/project/pyBKT/)、[FSRS 发布记录](https://pypi.org/project/fsrs/)。两库均为 MIT 许可，实施时更新依赖锁与开源声明。首先在 Python 3.12 验证候选版本和 API；必要的版本调整须记录原因及结果，不能静默换成自写算法。

在线服务安装完整推断／调度依赖；FSRS 优化依赖装入独立离线校准环境并提供真实可执行入口。默认参数能运行完整算法，但不等于针对本用户已校准。

## 3. 核心数据流

```text
Web / CLI 作答 → 统一批改及提示识别 → 不可变证据快照
  → pyBKT 更新知识估计 → 合格结果更新 FSRS 卡片和日志
  → 原子保存状态与计划 → 两端显示能力、复习到期及推荐理由
```

BKT 管理技能掌握，FSRS 管理记忆与到期，两者分开存储。长期未登录或复习逾期不直接把 BKT 清零。

所有概念都初始化 BKT 配置和 FSRS 新卡片。无证据仍显示“待诊断／尚未形成复习证据”，不把先验当作已测能力，也不把全部未学概念列为逾期复习。

## 4. Q-Matrix 与证据约束

沿用题目 `concept_keys` 形成显式 0/1 映射。事件保存题目映射、题型、难度、评分来源、置信度、辅助等级和证据策略版本快照；LLM 不能直接写掌握状态。

- 不同题目只计一次独立证据；相同请求幂等；重放按事件时间、ID 固定排序。
- 高置信、确定性评分、单知识点作答为可靠观测。低置信／未知判分、阅读和上传不制造掌握证据。
- 独立与提示辅助使用 pyBKT 不同观测类别及版本化参数；撤销前版自定义 0.35 加权公式。
- 辅助正确不增加独立达标计数；已看答案的 `solution` 不进入 BKT 观测。
- 综合题保存表现并触发单点诊断，不把一次错误归因到所有知识点，也不由一次综合正确认定全部掌握。
- `llm_rubric:*` 保留为待核实评价，不产生可靠 BKT／FSRS 正向更新。
- 服务端从提示事件识别辅助等级，客户端不能通过提交 `none` 隐藏提示。

## 5. BKT 接入

薄适配层只负责数据转换、库调用、参数版本和输出契约，推断与拟合交给 pyBKT。

初始参数集为实验配置：先验 0.2、学习率 0.1，独立观测猜对率 0.25／失误率 0.1，提示观测猜对率 0.75／失误率 0.05。经典技能状态不加入按日遗忘，记忆调度由 FSRS 管理。验证有限性、概率边界及观测可辨识性；不把初始值标成训练结果。

使用库推断重放相同合格事件。保留 API 的状态与证据计数字段，增加库／算法／参数版本、证据范围和哈希、校准状态。`mastered` 标签要求后验至少 0.8，并且至少两道不同题、难度至少 2、独立可靠正确，最近可靠单点证据不是错误。标签门槛是业务保护，不改变算法公式。

无证据返回 `unknown` 和空用户掌握估计。库调用或状态校验失败时回滚，保留原状态并明确报错，不回退旧规则。算法由后端统一固定，版本字段只用于审计／升级。

## 6. 完整 FSRS 接入

每个知识点作为一个复习单元保存完整 Card。概念配不同测试题是项目的聚合策略，其实际回忆测量效果需要另行评测，不能由“采用 FSRS”自动保证。

- 使用库的完整默认权重、学习／再学习步骤，初始目标保持率 0.9。为确定性重放关闭随机 fuzzing，其他调度由库计算；设置整体版本化。
- 保存完整序列化状态，包括稳定性、难度、due、last_review 和学习／复习／再学习阶段，不只保存下次日期。
- 每次更新保存原生 ReviewLog、事件 ID、评分依据、参数版本和前后状态。重试、刷新或重放不再次延后到期。
- 独立错误映射 `Again`；提示辅助正确表明未独立回忆，也映射 `Again` 并显示原因；可靠独立正确默认 `Good`。
- 完整支持 `Again/Hard/Good/Easy`。复习时允许回忆难度自评，服务端禁止错误／提示／看答案被标成 `Good/Easy`；独立正确可选 `Hard/Good/Easy`。不由客户端计时自动认定容易。
- 不确定评分不更新卡片或延期，保留事件并提示待核实。首次合格作答同样进入库的学习过程。
- 按库的精确时间处理分钟级学习步骤及长期到期，不按天取整替代算法。持久化为 UTC，展示用户时区。
- 使用库的 JSON 接口恢复 Scheduler、Card 和 ReviewLog；使用库接口计算 retrievability，标为记忆模型预测，与 BKT 技能估计分开展示。

完整性需以锁定库的直接调用对照验证，覆盖四种评分、全部阶段、短／长间隔与 JSON 恢复。仅安装包或运行示例不算接入完成。

## 7. 推荐和教学模式

用 `policy_v2` 替换原简单排序：恢复未完成任务；硬性过滤前置不足的候选；综合目标重要性、BKT 状态／证据不确定性、FSRS 到期程度及可用时间排序，返回分项与理由。截止日期不降低前置和证据要求。

未知关键概念采用有限预算诊断，按不同题目／概念消耗，避免反复返回已完成初始诊断。支持首次学习、误区修复、定向练习、迁移测试、阶段评估、到期复习；模式进入教学请求与课堂记录，继续校验知识点和教材引用。

计划与下一动作采用同一函数和请求时点计算当前到期，避免隔天读取旧快照。GET 不调用模型、不创建完成事件。未经真实验证的迁移题不宣称具备测量效度。

## 8. 数据结构和事务

在当前迁移链之后新增结构，实施前核对实际 HEAD：

| 结构 | 内容 |
|---|---|
| 空间算法元数据 | 固定启用的 BKT、FSRS 版本和参数版本；无启停开关 |
| `review_states` | 用户／空间／概念归属、完整 Card JSON、due、Scheduler 版本；每概念一行 |
| `review_sessions` | 用户／空间／概念、课堂／题目、幂等键、原到期周期、状态；每概念至多一个活动会话 |
| `review_logs` | 原生 ReviewLog JSON、唯一关联事件、参数版本，供回放与优化 |
| 现有 JSON 增量 | Q-Matrix、证据快照、BKT 元数据、推荐分项及教学模式 |

统一作答服务在一个事务内保存事件、BKT、FSRS、计划和结果。通用与复习提交共用服务，校验会话／题目，不能绕过调度或重复计分。新表使用归属约束与登录用户过滤；永久删除按依赖清理日志、会话和卡片。

CPU 推断不能阻塞异步主循环；拟合只在离线校准入口执行。每个请求隔离可变库对象，缓存按空间、事件截面和参数版本隔离，不共享跨用户训练状态。

## 9. Web、CLI 与报告

- Web 增加复习、7／30 天报告和只读算法状态，显示两个算法统一启用及校准状态；移除算法开关与旧规则比较。
- 复习可列表、开始／恢复、作答、选择回忆难度，显示下一次到期。仅用户明确开始／提交触发模型调用和学习写入。
- 报告确定性生成能力分布、进步、独立／辅助证据、易错点、复习完成及推荐理由；低证据不展示虚假高精度。
- CLI 增加 `review list/start/submit`、`report --days 7`、只读 `algorithms`，兼容 `--space`、`--json` 和既有交互课堂。
- 任务完成以课堂已读且练习均已提交为准，保存幂等开始／完成事件，但不由它们提升掌握。账号／空间切换沿用迟到响应保护。

新增 API 均在 `/api/v1/study-spaces/{id}`：`GET /q-matrix`、`GET /algorithms`、`GET /reviews`、`POST /reviews/start`、`GET /reviews/{rid}`、`POST /reviews/{rid}/submit`、`GET /report?days=7`。`/attempts` 和 `/lessons` 复用统一复习／提交服务；不提供禁用或切回规则接口。

## 10. 校准与评测

固定数据集清单记录版本、来源、种子、内容哈希，按学习者拆分拟合／验证／测试集。每个下一题预测在看到本题观测前完成，防止数据泄漏。

pyBKT 使用原生 EM 和观测类别拟合；FSRS 校准调用官方 optimizer 的参数及目标保持率优化，可使用原始日志重调度。提供实际可执行入口，不用自写网格或占位函数替代。

默认参数标记未针对本用户校准；样本不足明确返回不足，不逐次答题临时拟合。产物包含库／算法／参数版本、证据范围和指标，验证后方可发布为统一配置。

报告 Brier score、log loss、误判率和混淆计数，分别观察独立／辅助结果；复习保持率、任务完成率的分母为空时返回空值及原因。比较初始与拟合参数、升级前后算法，不为比较重新引入旧规则。

首版数据集为自有合成序列与人工案例，只证明流程与实现；真实用户数据使用另行授权，不提交 Git，不由合成评测宣称真实教育提升。

## 11. 已授权的清空与切换

删除范围已确认，不重复索取删除授权。新功能与临时数据库验证通过后，对本项目实际配置执行一次性切换：

1. 核对目标库和资料根目录，停止本项目写入与索引，避免清理时生成新记录；不删除仓库或重置未提交代码。
2. 共用空间删除／清理服务，清空所有用户的空间和关联记录，不删除整库文件，以保留账号、模型配置及凭证。
3. 清理原文、暂存文件、章节、向量、计划、学习事件和学习调用审计；取消旧索引，擦除含教材摘要的检查点。
4. 尝试删除远端文件；失败或在途上传保留最小墓碑及重试句柄，不能为追求零行丢失远端清理能力。远端未确认删除时明确记录。
5. 已清理墓碑按依赖移除；待清理句柄继续保护原凭证。执行新迁移后，核对零可用旧空间和零旧学习正文，账号和配置保留。
6. 重新建空间时初始化双算法。保存删除计数、算法版本及清理状态，不输出学习正文或凭证；不自动保留旧记录副本，也不遍历删除未知外部备份。

清空通过独立一次性管理命令执行，不嵌入常规迁移或每次启动；再次启动／部署不得再次删除新学习记录。

不重复计分、依赖过滤、低置信保守处理继续保留为证据约束。历史验收文档可保留历史标记，当前 README、OpenAPI、中文／英文说明按统一启用行为更新。

## 13. 实施顺序与验收

顺序为：验证开源依赖与 API → 算法与数据层 → 统一作答／复习 → 推荐与报告 → Web／CLI → 全套回归 → 已授权的真实清空和切换。

必须验证：

1. 与 pyBKT 直接调用对照推断、重放和拟合；独立／提示／错误／综合／无证据差异可解释。
2. 与 py-fsrs 直接调用对照四评分、全部阶段、分钟／长间隔、难度／稳定性／记忆预测及序列化恢复。
3. 所有新空间及新增概念初始化双算法；无旧规则回退、无停用入口；无证据仍待诊断。
4. 重试、重放、重启、重复题、提示和并发提交不重复计分／延期，失败事务回滚。
5. 前置、诊断预算、教学模式、到期推荐、计划与报告一致，久未登录不清零技能。
6. 用户／空间隔离、永久删除、远端清理、迟到上传及复习数据清理覆盖 SQLite／真实 PostgreSQL。
7. 临时既有数据库升级与清空测试通过，失败可恢复；重复启动不再清空；账号及模型配置保留。
8. 原生 BKT 拟合和 FSRS optimizer 在独立校准环境实际运行，保留数据版本、测试集隔离和对比结果。
9. Web 桌面／移动端与独立 CLI 完成建空间、诊断、学习、复习、报告及重登恢复，完整检查与构建通过。

完整算法接入与真实学习效果分别判定：前者以开源对照和集成验证，后者需要真实长期数据，不能由合成演示替代。

本版已经用户确认；实施计划见 [BKT + FSRS 实施计划](../plans/2026-10-19-m3-open-source-bkt-fsrs.md)。计划审阅及执行方式选择后进入开发。用户已经授权清空学习数据，不再重复请求该项授权。
